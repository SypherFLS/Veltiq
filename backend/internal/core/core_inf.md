Порядок, который обычно работает
core/domain — импорт (статусы), чек в том виде, в каком он «истина» после парсинга. Пара строк, без фанатизма.
core/ports — минимум интерфейсов: сохранить/прочитать импорт, сохранить/списать чеки, парсер Parse(…) → чеки. Без Postgres и без CSV в этих файлах.
core/service — один сценарий до конца осмысленного шага: например «создать импорт → вызвать парсер → сохранить чеки → пометить успех/ошибку». Логику статусов держи здесь.
Тесты на сервис с фейковыми реализациями портов (в памяти, заглушка парсера). Так ты проверяешь ядро до базы и настоящего парсера.
infrastructure — подключить одну БД и реализовать те же порты (репозитории).
modules — один реальный парсер (один формат), который подходит под интерфейс из п.2. Подставляешь его в main.
После этого цепочка живая: файл → чеки в базе. Уже потом — вторая ветка портов для базовой аналитики, Марков, HTTP.
